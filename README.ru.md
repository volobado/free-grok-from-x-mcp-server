# Бесплатный Grok из X: CLI в терминале и MCP-сервер

Grok, который идёт с вашим аккаунтом X, из терминала и из ИИ-агентов (Claude Code, Antigravity,
любой MCP-клиент). Без ключей и без платного API xAI: `grokx` работает со страницей Grok в
**вашем собственном браузере, где вы вошли в X**, поэтому возможности и лимиты те же, что на x.com/i/grok.

[English version](README.md)

## Как это устроено

Два канала, CLI сам выбирает рабочий и при сбое переключается на другой:

| Канал | Что нужно | Когда удобен |
| :--- | :--- | :--- |
| **1. Расширение Chrome** (основной) | Расширение из `extension/` в обычном Chrome, вход в X | Ваш повседневный браузер |
| **2. Отдельный Chrome по CDP** (запасной) | `grokx --launch`, один раз войти в X в этом окне | Без расширения, свой профиль |

```
grokx (CLI / MCP) ──ws://127.0.0.1:29191──> демон grokx ──> service worker расширения ──> вкладка x.com/i/grok
                  └──CDP 127.0.0.1:9333──> отдельный Chrome (~/.grokx/chrome-profile) ──> вкладка x.com/i/grok
```

Ответ берётся из сетевого потока Grok, а не из разметки страницы, так что не мешают ни смена вёрстки,
ни язык интерфейса. Grok в X («AI agent», ноябрь 2026) ходит по WebSocket `wss://grok.com/ws/mgw/`:
текст ответа приходит событиями `response.chunk` в канале `CHANNEL_ASSISTANT_RESPONSE`, служебные
каналы вроде «Thinking about your request» пропускаются, конец отмечает `response.output_text.done`.
Старый HTTP-поток `add_response.json` тоже поддерживается. Перехватчик один на оба канала: `extension/injected.js`.

Если X опять поменяет протокол, ошибка «no Grok answer stream» сама покажет запросы страницы и кадры
WebSocket после отправки вопроса: по ним видно, что поправить.

Безопасность:

- Вопрос вводится в поле и отправляется **только клавишей Enter**. Кнопки страницы grokx не нажимает
  (там есть кнопки оплаты и подписки).
- Локальный демон пускает только локальные программы и расширения браузера. Веб-страницы получают
  отказ, так что ни один сайт не прочитает ваши вопросы и не будет управлять вашим Grok.
- CDP-канал работает только со своим Chrome на порту 9333 и не трогает отладочный Chrome на 9222.

## Установка (Windows)

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/) и Chrome.

1. `git clone https://github.com/volobado/free-grok-from-x-mcp-server`, затем `setup.bat`
   (зависимости, команды `grokx`, `grokx-cli`, `grokx-mcp` в `~/.local/bin`, самопроверка).
2. Chrome: `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → папка `extension`.
3. Войдите в X в этом Chrome. Открывать https://x.com/i/grok не обязательно: при первом вопросе
   расширение само откроет вкладку в фоне. На странице Grok в правом нижнем углу появится значок
   **GrokX: ready**. Если Chrome спросит доступ к устройствам в локальной сети, разрешите.

Пока демон не запущен, в «Ошибках» расширения копятся `ERR_CONNECTION_REFUSED`: это безвредно,
расширение просто стучится к демону.

## Использование

```powershell
grokx                                   # интерактивный режим
grokx "Объясни трансформеры простыми словами"
grokx -n "Вопрос в новом чате"
Get-Content main.py | grokx "Проверь обработку ошибок"
grokx "Сводка" > answer.md              # в файл/пайп идёт чистый текст
grokx --cdp "..."                       # только отдельный Chrome
grokx --bridge "..."                    # только расширение
grokx --launch                          # запустить отдельный Chrome (один раз войти в X)
grokx --status                          # состояние каналов
grokx doctor                            # полная диагностика
grokx daemon start|stop|restart|status|logs
grokx reload-extension                  # перезагрузить расширение с диска после правок
```

В интерактивном режиме: `/new`, `/copy`, `/status`, `/doctor`, `/clear`, `/help`, `/exit`.
Enter отправляет, Alt+Enter или `\` в конце строки переносит строку, Ctrl+C останавливает ответ
(и в Grok тоже), Ctrl+D выходит.

## MCP

```powershell
claude mcp add -s user grokx -- <путь-к-репозиторию>\.venv\Scripts\python.exe -m grokx_cli.mcp_server
```

Инструменты: `grok_query(prompt, new_chat=False)`, `grok_new_chat()`, `grok_status()`.

## Где что лежит

- `~/.grokx/grokx.log` лог демона, `history.txt` история ввода, `chrome-profile/` профиль CDP-Chrome.
- Переменные: `GROKX_PORT` (29191, в расширении этот же), `GROKX_CDP_PORT` (9333), `GROKX_HOME`.

## Тесты

```powershell
.venv\Scripts\python.exe tests\test_bridge.py   # протокол демона
.venv\Scripts\python.exe tests\test_e2e.py      # Chromium + расширение и настоящий Chrome по CDP на макете Grok
```

`test_e2e.py` гоняет копию расширения на отдельном порту, рабочий демон и браузер не мешают. Макет
повторяет протокол, снятый с живого x.com, включая то, что страница первую секунду после загрузки
не принимает Enter. Проверено и вживую: ответ, новый чат, уточнение по контексту, пайп, MCP.

## Ограничения и оговорка

- Нужен вход в X; лимиты Grok для вашего аккаунта те же, что в браузере. Когда бесплатный лимит кончился, grokx так и говорит (у Grok это `usage_limit_reached`).
- Картинки и вложения в ответах приходят только текстом.
- Демон, запущенный из-под MCP, завершается вместе с MCP-хостом и при следующем вопросе стартует заново.
- Неофициальный личный инструмент, не связан с X и xAI. Он автоматизирует страницу, на которой вы
  залогинены, а правила X это могут не разрешать: используйте на свой риск и без злоупотреблений.
  Изменение протокола на стороне X может сломать его в любой момент.
